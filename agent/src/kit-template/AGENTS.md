# Kit Development Guidelines

You are working on a **kit** — a self-contained mini-app with a React frontend and Hono backend.

## Project Structure

```
<kitId>/
├── kit.json              # Manifest (id, name, description, icon, version, enabled)
├── package.json          # All dependencies (frontend + backend)
├── vite.config.ts        # Vite config with @/ alias
├── components.json       # shadcn CLI config
├── tsconfig.json
├── index.html            # Vite entry HTML
├── src/                  # React frontend
│   ├── App.tsx           # Main component
│   ├── main.tsx          # Entry point
│   ├── index.css         # Tailwind + shadcn/ui theme variables
│   ├── lib/utils.ts      # cn() helper
│   ├── lib/kit.ts        # kit.fetch(), native bridge (setTitle, setMenu, etc.)
│   └── components/ui/    # shadcn/ui components (added via CLI)
├── server/
│   └── index.ts          # Hono backend (default export)
└── dist/                 # Built frontend (generated by vite build)
```

All dependencies (React, Hono, and any additional packages) go in the root `package.json`.

## Frontend

### UI Components
Use **shadcn/ui** for all UI components. Add components via:
```bash
bunx shadcn@latest add button card input select badge table tabs dialog sonner
```

Import components from `@/components/ui/`:
```tsx
import { Button } from "@/components/ui/button";
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card";
```

Use the `cn()` utility for conditional classes:
```tsx
import { cn } from "@/lib/utils";
<div className={cn("p-4", isActive && "bg-accent")} />
```

### Styling
- Tailwind CSS v4 is pre-configured with shadcn/ui CSS variables
- Use shadcn's semantic color tokens: `bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`, etc.
- Do **not** install other UI libraries (Material UI, Chakra, Ant Design, etc.)

### Layout
Kits run in a desktop iframe AND an iOS WKWebView — always design mobile-first:
- Start with a single-column layout that works on small screens, then enhance for wider viewports with `sm:`, `md:`, `lg:`
- Use `w-full max-w-lg mx-auto` (or similar) to center content and prevent overly wide layouts on desktop
- Tap targets must be at least 44×44px — use `min-h-11 min-w-11` on interactive elements
- Avoid hover-only interactions — anything revealed on hover must also be accessible via tap
- Use `gap-*` and `p-4` (not `p-1` or `p-2`) for comfortable touch spacing
- Prefer vertical scrolling over horizontal scrolling
- Test that text is readable without zooming (minimum `text-sm` / 14px)
- **Input font size:** All `<input>`, `<textarea>`, and `<select>` elements must have `font-size: 16px` or larger on mobile. iOS Safari auto-zooms the page when focusing inputs smaller than 16px. Use `text-base` (not `text-sm` or `text-xs`) on form elements.

### API Calls
Use `kit.fetch()` from `@/lib/kit` for all backend calls. It handles routing automatically — **use the same paths as your Hono routes**:
```tsx
import { kit } from "@/lib/kit";

const res = await kit.fetch("/items");
const data = await res.json();
```

**IMPORTANT:** Never use `fetch()` directly for kit API calls. Always use `kit.fetch()` — it ensures the correct routing prefix is applied.

### Native Bridge

`kit` also exposes methods to control the native iOS nav bar. These are no-ops on desktop/browser:

```tsx
import { kit } from "@/lib/kit";

// Set the nav bar title (overrides the default kit name)
kit.setTitle("My Feed");

// Add a dropdown menu to the nav bar (top-right)
kit.setMenu([
  { id: "refresh", label: "Refresh", systemImage: "arrow.clockwise" },
  { id: "settings", label: "Settings", systemImage: "gear" },
]);

// Handle menu item taps
kit.onMenuAction((actionId) => {
  if (actionId === "refresh") loadData();
});
```

- `systemImage` values are **SF Symbol** names (e.g. `"arrow.clockwise"`, `"gear"`, `"trash"`)
- Call `setTitle` / `setMenu` early (e.g. in a `useEffect` on mount) so the nav bar updates before the user interacts
- Call `onMenuAction` once to register a single callback — later calls replace the previous one

## Backend

The backend is a **Hono** router exported as the default function from `server/index.ts`:

```ts
import { Hono } from "hono";
import type { KitContext } from "../../../agent/src/kits-server";

export default function(ctx: KitContext): Hono {
  const app = new Hono();

  app.get("/items", (c) => {
    const rows = ctx.db.prepare("SELECT * FROM my_items").all();
    return c.json(rows);
  });

  return app;
}
```

- **Frontend and backend use the same paths.** If the backend defines `app.get("/items")`, the frontend calls `kit.fetch("/items")`.
- `ctx` provides: `kitId`, `db` (shared SQLite), `config` (manifest), `kitsDir`

## Dependencies

All dependencies go in the kit's root `package.json`. To add a new package:
```bash
bun add rss-parser    # runtime dependency (server or client)
bun add -d some-tool  # dev dependency
```

## Database

All kits share a single **SQLite** database via `ctx.db` (using Bun's built-in SQLite driver).

- **Namespace tables** with a prefix to avoid collisions (e.g. `mykit_items`, `mykit_settings`)
- **WAL mode** and **foreign keys** are already enabled
- **Use prepared statements** — never interpolate user input into SQL:
  ```ts
  // Good
  ctx.db.prepare("SELECT * FROM items WHERE id = ?").get(id);
  // Bad — SQL injection risk
  ctx.db.prepare(`SELECT * FROM items WHERE id = ${id}`).get();
  ```
- Create tables with `IF NOT EXISTS` so the kit is idempotent on reload

## Build & Reload

After making changes:
1. **Build** the frontend: the `build` action runs `bun install` + `vite build`
2. **Reload** the backend: the `reload` action hot-reloads the Hono router

Both are triggered via the `manage_kit` tool — you don't need to run them manually.
